The dry-run gives dependency-ordered, file-level tasks for a runnable hosted
page, POST ingress, protocol client/common dispatcher, renderers, finish,
and tests rather than only generic MSAL wiring. It consumes an initial MFA
enrollment response without discovery/first-factor/start replay or an
authorize-challenge call, permits repeated/reordered required interaction,
and preserves the original OAuth request. It includes a synchronous
single-flight transaction guard, current token/link snapshots, opaque
same-authority links, memory-only state, history restoration and expiry
restart, safe errors/diagnostics, browser finish POST, and validated callback.
It separates planned/mocked coverage from unrun live checks and manual tenant
work. It does not fabricate exact missing request fields.
